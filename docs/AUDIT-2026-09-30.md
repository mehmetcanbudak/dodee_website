# Dodee project audit and remediation

> Historical snapshot of the initial September 30 remediation pass. The subsequent completion pass removed signup previews and unverified public contact/partner claims, archived the old clue campaign, and added portable browser/performance CI. Use [the completion checklist](REMAINING-WORK-2026-09-30.md) for current implementation, release status, and remaining external acceptance; the counts below describe the initial pass.

Date: September 30, 2026 (Europe/Istanbul).

## Scope and starting state

Reviewed both implementations, their eight public pages each, shared components, browser scripts, styles, public assets and references, SEO, optional auth/database helpers, Worker/build configuration, dependency graph, tests, deployment instructions, and Git boundaries.

- Root: static HTML/CSS/JavaScript website, branch `website`, starting HEAD `089698ba`.
- `sites/dodee-next`: independent nested React/vinext Git repository, starting HEAD `70891af`.
- The nested homepage and stylesheet already had local modifications. The supplied hero/cloud artwork and those changes were preserved. The existing root `dist/` and nested source archive were preserved, not treated as deployment inputs.
- `.agents`, `.claude`, `.pi`, private environment files, and historical generated archives are tooling/private artifacts, not application source. No credentials were read or copied into outputs.
- Existing Figma/audit documents were read as historical design context. This pass does not claim new pixel parity with the live Figma file.

| Episode cards ignored `hidden` because CSS set their display | Global hidden semantics restored; filter controls progressively enable and support nested SVG clicks/keyboard activation. |
| Clue loading failures looked like campaign completion | Distinct unavailable/completed states, timeout and response validation; guessing/share UI only appears after a valid active clue loads. |
| Scroll reveal could leave tall sections or focused controls invisible | Early intersection handling and immediate keyboard-focus reveal; restored-scroll and reduced-motion behavior repaired. |
| Mobile art obscured content and produced horizontal overflow | Decorative desktop art no longer covers phone/tablet controls; section overflow, hero sizing and scroll hint spacing corrected. |

| No reproducible quality gate | Added HTML/asset/link/ARIA/sitemap/syntax validation, behavior tests, output-isolation tests and CI configuration. |

Static response protections now include a script CSP without `unsafe-inline`, `object-src 'none'`, restricted framing/form submission, `nosniff`, referrer policy and disabled camera/microphone/geolocation. Inline **styles** remain allowed because the existing artwork uses inline positioning. Actual production headers still require a release check.

## Remaining work and acceptance boundaries

1. **Choose the production implementation and origin.** Both designs remain valid, independent repositories. A root commit does not capture nested repository changes. Configure the React `SITE_URL` if it is chosen, or update static canonical/robots/sitemap values together if its domain changes.
2. **Connect a real email service if subscriptions are required.** This needs the intended provider/account, recipient list, consent requirements and tested delivery/unsubscribe behavior. Current behavior is intentionally truthful and does not subscribe anyone.
3. **Verify business content.** Confirm channel/social destinations, mailbox ownership, episode availability, sponsor relationships and publication rights with the owner. Supplied React sponsor badges are not independently verified official brand artwork. Historical `verifiedAt` values are not fresh external confirmation.
4. **Decide the next clue campaign.** The static campaign's April 10–22 window is historical and correctly shows completed state. New clues/dates need actual campaign content, not invented release facts.
5. **Perform deployed and human acceptance.** Local browser/Worker checks do not prove DNS, live hosting policies, real email service behavior, physical-device rendering or VoiceOver/NVDA usability. Automated accessibility results are scoped checks, not a conformance certification.
6. **Commit and release deliberately.** Changes are local in both repositories. No production deployment, push, account change, email or public message was performed. Existing archives and source artwork remain intact.
